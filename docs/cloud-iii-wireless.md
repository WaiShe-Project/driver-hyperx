HyperBatteryMonitor 的做法可供借鉴：用电量查询的应答来验证候选控制接口是否正确，记住可用的接口，重连后重新验证。

## 2. 要回答的问题

### 设备可达性（S1）

1. 手头的接收器产品 ID 是哪一个？
2. Windows 为接收器枚举出哪些 HID 接口与顶层集合？哪一个是控制接口？音频接口不应被触碰。
3. 未安装 NGENUITY、无管理员权限时，用户态程序能否在控制接口上收发所需的报告？命令需要以输出报告还是特性报告发送？
4. 电量、充电状态能否读取？电量是精确百分比还是档位？
5. 固件版本、序列号能否读取？

### 链路状态

6. 接收器在线而耳机关机时，各查询返回什么？如何与“耳机在线且电量为某值”区分？
7. 耳机开机、关机时接收器是否主动上报？
8. 耳机自动关机（长时间无音频）后的表现是否与手动关机相同？

### 麦克风静音

9. 按下静音键时，接收器在哪个接口上报什么？
10. 静音状态能否主动查询？如果只能等事件，Bridge 启动后到第一次按键之前，该能力应为 `unknown`。
11. 收起或拔下麦克风杆是否也产生事件？与按键静音如何区分？

### 充电

12. 充电中电量读数是否可信？是否存在偏高现象？
13. 充电中耳机若同时开机使用，各状态是否正常上报？

### 不干扰（需求 HEAD-06）

14. 持续监听输入报告期间，音频播放与录音是否正常？
15. 耳机上的音量滚轮、静音键是否照常工作？

### 厂商软件共存（S2）

16. NGENUITY 运行时，读取是否仍然可靠？事件是否仍能收到？
17. 两者同时查询时，应答是否会串到对方？

### 设备归并（S6）

18. 接收器的多个接口能否可靠地归并为一个端点？
