## 2. 协议

来源：HyperBatteryMonitor `Devices/Cloud3WirelessAlternateReceiverDevice.cs`、`Hid/HidConnection.cs`（MIT，2026-11-14 读取）；未登记来源的部分来自本项目抓包。见 [PROVENANCE.md](../PROVENANCE.md)。

### 2.1 传输

| 项 | 实测结论 |
| --- | --- |
| 控制接口 | `MI_03` 第 1 个顶层集合，用途 `FF13:0001`，输入、输出报告各 62 字节 |
| 打开方式 | 读写权限打开成功，不需要管理员权限 |
| 请求 | 写输出报告：报告 ID `0x66`，第 1 字节为选择符，其余补零 |
| 应答 | 输入报告，第 0 字节 `0x66`，第 1 字节为对应选择符；2 至 5 ms 内到达 |
| 广播 | 输入报告会送达打开该接口的**所有**句柄。其他进程（如 NGENUITY）的查询应答也会被本程序读到，反之亦然 |
| 其他集合 | `MI_03` 第 2 个（`000C:0001`）、第 3 个（`000B:0005`）顶层集合未使用 |

HaloBattery 提到部分 HyperX 接收器只接受特性报告；`0FCC` 接收器的控制集合特性报告长度为 0，输出报告工作正常。

### 2.2 查询（请求—应答）

| 能力 | 选择符 | 应答解析 | 来源 |
| --- | --- | --- | --- |
| 电量 | `89` | 字节 4 为百分比。字节 2、3 同为 0 表示耳机不在线 | HyperBatteryMonitor |
| 充电状态 | `8A` | 字节 2：1 充电中，0 未充电。HaloBattery 另称 2 为已充满，未验证 | HyperBatteryMonitor |
| 麦克风静音 | `86` | 字节 2：1 静音，0 未静音 | HyperBatteryMonitor |

电量应答字节 2、3 在实测中缓慢下降（`0E C9` → `0E C4`），推测为大端毫伏电压（约 3.78 V）。未确认。

### 2.3 主动上报

| 选择符 | 观察到的报文 | 解读 | 来源 |
| --- | --- | --- | --- |
| `0A` | `66 0A 01 01` / `66 0A 00 01` | 按静音键：静音 / 取消静音。字节 3 含义未知 | HyperBatteryMonitor 有此选择符；实测确认 |
| `0D` | `66 0D 0E CA 2F` | 电量通知，格式同 `89` 应答 | HyperBatteryMonitor 有此选择符；实测确认 |
| `0C` | 未观察到 | 充电状态通知 | HyperBatteryMonitor |
| `07` | `66 07 01` / `66 07 00` | 推测为麦克风插入 / 拔下 | 本项目抓包，推断 |
| `02` | `66 02 14` | 耳机开机时出现，含义未知 | 本项目抓包 |
| `0F` | `66 0F 01` | 耳机开机时出现，含义未知 | 本项目抓包 |
| `0B` | `66 0B 01` | 耳机开机时出现，含义未知 | 本项目抓包 |

## 3. 问题与结论

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 接收器产品 ID | `0x0FCC` |
| 2 | 控制接口 | 见 2.1。不需要打开音频接口 |
| 3 | 无厂商软件、无管理员权限能否收发；输出还是特性报告 | **能**，使用输出报告。以 Administrators 仅拒绝的令牌运行，NGENUITY 已退出时全部查询成功 |
| 4 | 电量、充电能否读取；精度 | 能。电量为精确百分比 |
| 5 | 固件版本、序列号 | 序列号可通过系统 HID 字符串读取；固件版本尚无已知命令 |
| 6 | 接收器在线而耳机关机 | 电量应答字节 2、3 为 0。**充电与静音查询此时也返回 0**，与“在线、未充电、未静音”相同，必须以电量应答判定的在线状态为前提 |
| 7 | 开关机时是否主动上报 | **都会**。关机：`66 0B`、`66 02`、`66 0D`（字节 2、3 为 0 的电量通知）、`66 08 01`、`66 09`、`66 07`、`66 0F`，4 ms 一条。开机：`66 02 14`、`66 0D <电量>`、`66 07 01`、`66 0F 01`，约 1 秒后 `66 0B 01`。**开机时不上报充电与静音状态**，Bridge 必须在耳机上线后主动查询 `8A` 与 `86`（2026-11-14 实测） |
| 8 | 自动关机 | 未单独验证；推测与手动关机相同 |
| 9 | 静音键上报 | 选择符 `0A`，见 2.3 |
| 10 | 静音状态能否主动查询 | 能，选择符 `86`。Bridge 启动后可立即得到当前状态，不必等待按键 |
| 11 | 麦克风杆拔插 | 产生选择符 `07` 的上报，与静音键可区分。含义为推断 |
| 12 | 充电中电量是否可信 | 未测 |
| 13 | 充电中使用 | 未测 |
| 14 | 监听期间音频是否正常 | 测试期间未发现异常，未做专门的播放与录音测试 |
| 15 | 耳机按键是否正常 | 静音键正常工作 |
| 16 | NGENUITY 运行时读取与事件 | 读取可靠 |
| 17 | 同时查询时应答是否串到对方 | 会。输入报告广播给所有句柄（见 2.1） |
| 18 | 接口归并为端点 | 接收器的全部 HID 节点共享同一个容器 ID，可据此归并 |

### 对实现的影响

- `battery.charging` 与 `headset.mic_mute` 只能在电量应答显示耳机在线时采信，否则返回 `unavailable`。
- 应答按选择符匹配，并容忍收到非本次请求的报告。
- 静音状态以主动上报为主，Bridge 启动或耳机上线时主动查询一次，之后不需要轮询。
- 耳机开机时的上报可用于立即刷新状态，不必等待下一次轮询。
